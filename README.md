# 壁鉴新生

“壁鉴新生”是面向校赛展示的壁画智能观察与保护决策工作台。核心闭环不是“让AI直接修图”，而是：

> 建立图像档案 → AI提出疑似区域 → 人工复核/驳回/补充 → 生成单页观察卡

当前版本优先保证校赛最关键的可演示性、证据链和边界说明：AI只提供图像观察候选，人工负责判断，观察卡记录证据。

**关于虚拟修复**：赛题将虚拟修复放在现场实战阶段，并限定使用千问办公与阿里云百炼。线上阶段只提交观察卡与演示视频，因此本工作台不做虚拟修复——对已丢失的壁画内容不做无依据补全，只做观察、标注与人工复核。

## 快速启动

Windows 10/11 下双击：

1. `install.bat`：创建 `.venv` 并安装依赖；
2. `run.bat`：启动网页应用。

PowerShell 手动启动：

```powershell
cd "C:\Users\sky.bob\Desktop\ai+校赛"
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py
```

浏览器打开终端显示的本地地址，通常为 `http://localhost:8501`。

## 三种工作模式

- **本地演示（无外部API）**：校赛现场首选。使用合成演示图和本地流程，不依赖网络和密钥，并明确标注“本地演示数据/非生成式AI”。
- **现场合规预览**：专门用于规则约束下的流程预演，界面会锁定 DeepSeek 等外部API，并提示现场按要求使用千问办公与百炼。
- **线上研发 / 校赛演示**：默认模式。用于规则允许、网络和密钥稳定时的研发测试，接入 DeepSeek Vision 做图像观察。

不要把线上研发模式的外部API结果包装成现场合规结果。演示时应主动说明当前模式、模型来源和哪些内容是预先保存的。

## 校赛线上提交：只准备两项成果

按照你们校赛线上提交要求，正式评审材料只有：

1. **一页 PDF《AI壁画观察卡》**：包含原图缩略图、疑似问题标记、AI观察说明、保护或数字展示建议、不确定性、人工复核提示、图片来源和工具来源。
2. **不超过2分钟的真实操作视频**：展示所选AI/大模型能力的实际使用过程，或展示主要工作流和结果流转。

PDF超过1页只评审第一页，视频超过2分钟只评审前两分钟。

线上阶段不要求提交源代码、数据库、训练数据、项目说明书、正式部署环境或算法精度报告。项目代码保留在本机，作用是帮助团队稳定生成观察卡和录制真实操作过程。

## 推荐校赛演示顺序

1. **01 建立档案**：填写任务编号、图像来源、授权说明，展示原始图像。
2. **02 AI观察**：点击结构化观察，展示整体观察、候选框、直接证据和不确定性。
3. **03 人工复核**：拖拽矩形新增候选，或修改坐标；分别标记“待复核/已确认/已驳回”，写入人工备注。
4. **04 观察卡**：下载单页 A4 PDF，突出原图、标注图、人工状态、来源授权和过程记录。流程到此结束。

推荐录制“上传/演示图—AI观察—人工确认—下载观察卡”这一条真实链路，不要把后端安装过程放进视频。

## API配置

将 `.env.example` 复制为 `.env`，按需填写：

```text
DEEPSEEK_API_KEY=你的DeepSeek密钥
DEEPSEEK_MODEL=deepseek-flash
# low更快更稳定；需要更细节时可改为original
DEEPSEEK_IMAGE_DETAIL=low
# 默认绕过Windows系统代理；只有在代理已验证可用时才改为1
WALL_MURAL_USE_SYSTEM_PROXY=0
```

也可以直接在网页左侧输入。不要把真实密钥放进代码、截图、PPT、GitHub 或视频。

- [DeepSeek Vision 官方文档](https://api-docs.deepseek.com/guides/vision/)

## 验收与边界

- 坐标严格使用 0—1000 归一化格式；0—1 小数不会被静默放大。
- AI候选框、人工编辑框、人工状态和备注进入 JSON、Markdown 与观察卡。
- 不做虚拟修复：丢失内容不猜测、不补全，观察卡明确标注 AI 候选与人工复核边界。
- 观察卡包含图像来源、授权说明、模型模式、复核数量、过程记录和免责声明。
- 演示图中的浅色剥落/裂纹与暗色斑块是合成的可见模拟异常，不代表真实文物病害。
- 真实图片必须有合法来源或明确授权；单张图像不能证明温湿度、盐分、微生物或污染物成因。

## 常见故障

### `check_hostname requires server_hostname`

这是旧版 pip 继承异常代理变量时的安装错误。当前 `install.bat` 会临时清除当前安装进程的代理变量、升级 pip 并重新安装依赖，不会修改 Windows 系统代理设置。

### `ProxyError`、`Unable to connect to proxy` 或 `EOF occurred in violation of protocol`

这通常是 Windows 的 `HTTP_PROXY`、`HTTPS_PROXY` 或 `ALL_PROXY` 指向了不可用代理。当前 `run.bat` 会清除这些变量，程序默认只直连，避免不可用代理让一次操作长时间卡住；如校园网络必须使用已验证代理，请在 `.env` 中设置 `WALL_MURAL_USE_SYSTEM_PROXY=1`。开启后程序会先试代理，再回退直连。

### DeepSeek失败时是否会导致整条流程中断

不会。对于任何能被Pillow正常读取的图片，系统会先统一为RGB JPEG并压缩后发送；实时API失败时会明确标记“本地兜底数据（DeepSeek未完成，未冒充AI）”，继续提供人工框选、复核和导出。兜底结果不当作AI识别结论，评委展示时必须如实说明。

### API 返回 401/402/403/422

先检查 Key、模型、账户额度和图片参数；校赛展示可切回本地演示模式，保留错误说明，不要临时伪装成实时AI结果。

### 现场网络不可用

提前运行本地演示模式并下载一份 JSON、Markdown、A4观察卡和区域图作为备用材料。
